# Glossary: yardr's words

Every word yardr uses for its own things, each with what it is. The first
sixteen are the yard's own, for what a person meets every day; the rest are
plain words kept on purpose, because they name general machinery.

| yardr | what it is |
|---|---|
| **yard** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-yard-light.svg"><img alt="yard" src="assets/pictograms/track-plan-yard-dark.svg" height="24"></picture> | one installation of yardr: its store, its crew and its depots |
| **depot** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-depot-light.svg"><img alt="depot" src="assets/pictograms/track-plan-depot-dark.svg" height="24"></picture> | a git repository or a plain directory that beads are worked in |
| **bead** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-bead-light.svg"><img alt="bead" src="assets/pictograms/track-plan-bead-dark.svg" height="24"></picture> | one durable piece of work (an issue, in a tracker) |
| **train** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-train-light.svg"><img alt="train" src="assets/pictograms/track-plan-train-dark.svg" height="24"></picture> | a bead whose children land on its branch and reach the base as one, after one review of the whole |
| **wagon** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-wagon-light.svg"><img alt="wagon" src="assets/pictograms/track-plan-wagon-dark.svg" height="24"></picture> | a child of a train on the fast lane: built in parallel, a quick run of the tests, no review of its own |
| **siding** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-siding-light.svg"><img alt="siding" src="assets/pictograms/track-plan-siding-dark.svg" height="24"></picture> | a stage where small shaped beads wait to leave as one bead, folded into a carrier when enough wait or long enough passes |
| **carrier** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-carrier-light.svg"><img alt="carrier" src="assets/pictograms/track-plan-carrier-dark.svg" height="24"></picture> | the one bead a fold makes from its members, holding each member's body as a part |
| **fold** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-fold-light.svg"><img alt="fold" src="assets/pictograms/track-plan-fold-dark.svg" height="24"></picture> | making one carrier bead out of several beads, closing each member folded into it |
| **question** | the type of the bead `yardr bead ask --new` makes for a question that is about no bead: it carries the ask and is nobody's to build, so nothing routes it and it is never reported unrouted; its asker closes it when the answer is on it |
| **crew** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-crew-light.svg"><img alt="crew" src="assets/pictograms/track-plan-crew-dark.svg" height="24"></picture>, crew member | the always-on agents of the yard, tied to no bead |
| **yardmaster** | the crew member that coordinates: shapes beads, keeps the line moving, answers people |
| **assembly** | the starter pack's group that tests an approved bead and lands it on the base |
| **line** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-line-light.svg"><img alt="line" src="assets/pictograms/track-plan-line-dark.svg" height="24"></picture> | what a bead travels in a depot: its flow's stages, the groups the routes put at them, and the agents and people bound to those groups; a pack is a line written down, bound to no one, and importing it into a depot makes one |
| **ask** <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-ask-light.svg"><img alt="ask" src="assets/pictograms/track-plan-ask-dark.svg" height="24"></picture> | one question as data on a bead (`yardr bead ask`), answered by picking an option, put aside, or declined, or taken back by whoever asked it (`yardr bead ask --take-back`), with why. A **secret ask** (`--secret <source>`) asks the operator for a declared source's credential: the server writes its answer to a file and keeps the value out of notes. It is typed hidden unless the source marks every asked mint input as not secret, in which case a field that supports the setting shows the value as typed. A **run ask** (`yardr bead ask <id> -`, with an `R: <command>` line on stdin) proposes one yardr command of a fixed list that is the operator's to give (a link's mail limit or kinds, where a linked yard's beads go, who a linked yard's crew member is in a source, a source's calls an hour, a grant of a source's calls, a new source a file declares with its declaration on the card, a user added or removed, a crew member's grants, a crew member's identity in a source, a setting, a link renamed, a bead's originator, a timer removed), or a user's own (their subscription to the yard's events, which parts their phone is told of): its card shows the command whole with the yard's own sentence for what it changes, and the approval of the one asked (`yardr bead answer <id> <ask> --approve`) has the yard run exactly that command, once. A **setup ask** (`--setup <pack> --crew <name>`) carries the whole setup of a pack's sources as one decision, the apply, the account and the grants: its card shows the declaration whole with the mint, the account to type unseen, and one option per preset rendered by the yard, and the approval (`yardr bead answer <id> <ask> <n> --secret`) has the yard apply the pack, take the account and grant the preset picked, once |
| **answer** | what one person did with one ask (`yardr bead answer`): the option picked with any words, words alone, put aside, or declined; for a secret ask, the names that were given, never the value; for a run ask the operator approved, the command the yard ran and what it printed; for a setup ask the operator approved, the preset picked and the names given, with the setup read as being carried out, ran or failed |
| **topic** | what questions that belong together stand under: a bead label with the prefix `topic:`; a bead's topic is its first such label |
| triage | the contributors pack's first stage: an issue or a pull request from outside waits there for a maintainer, before anything of it is built or run; a pull request's yes is of one commit (`accepted_head`): the one the label `accepted` was put on, or the one the bead's card in Decide showed when a person picked accepted; new commits on it bring the bead back here, with a card of the new head |
| review-post | the contributors pack's stage after a pull request's reviewer reports done or changes: the yard's own script (`post-review`, an exec group, as the GitHub App) posts the review the reviewer stored as a comment on the pull request, on the head the reviewer read and only when the hook made the bead's link, and sends the bead on, done to ciwait and changes to the contributor; a review it cannot post goes back to the reviewer once |
| ciwait | the contributors pack's stage for a reviewed pull request while the yard runs the depot's test command on its head merged into the base (`pr-ci`, an exec group of the yard's own): it tests only the head the reviewer recorded as `reviewed_head` (and, for a pull request that waited in triage, that a maintainer accepted), merged into the freshly fetched base, and holds the bead for any other; done records the head as `ci_head` and goes to approved, changes (a red run, a head that does not merge, or a person's push) goes back to the contributor, a bot's push back to review, new commits on a pull request a maintainer accepted back to triage, and the pull request's merge or close ends the bead |
| contributor | someone outside the yard who opened an issue or a pull request; in the contributors pack also the stage a pull request waits in for its author's next commits |
| maintainer | a person of the yard who decides what of a contributor's work the project takes; the contributors pack's group `maintainers` |
| flow <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-flow-light.svg"><img alt="flow" src="assets/pictograms/track-plan-flow-dark.svg" height="24"></picture> | the stages a bead of some type goes through, and the moves allowed between them |
| stage <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-stage-light.svg"><img alt="stage" src="assets/pictograms/track-plan-stage-dark.svg" height="24"></picture> | one step of a flow: a status or column, in a tracker (in the starter flow: backlog, new, review, review-security, clear, approved, merged, decide) |
| route <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-route-light.svg"><img alt="route" src="assets/pictograms/track-plan-route-dark.svg" height="24"></picture> | which group takes the beads of a stage; a route with no depot is a yard default, serving every depot that does not state its own route for the same beads; of the routes that match a bead the first in a named order takes it: urgency, asked for by name, estimate, the rest, own before default, id ([groups.md](groups.md#which-beads-a-route-takes)) |
| estimate | a bead label that says how hard or how large the bead is, one that begins `difficulty:` or `size:`; a route for one ranks after a route for a label asked for by name |
| group <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-group-light.svg"><img alt="group" src="assets/pictograms/track-plan-group-dark.svg" height="24"></picture> | who works a stage: a pool of agents, a script, people, or another yard |
| runner | how a group's work starts: `herdr` (an agent), `exec` (a command), `manual` (people), `peer` (another yard) |
| session | one agent working one bead in one stage |
| outcome | how a session says its stage ended (`done`, `changes`, `question`, `failed`); the flow picks the next stage |
| hook <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-hook-light.svg"><img alt="hook" src="assets/pictograms/track-plan-hook-dark.svg" height="24"></picture> | a webhook endpoint that turns an outside system's deliveries into events |
| source <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-source-light.svg"><img alt="source" src="assets/pictograms/track-plan-source-dark.svg" height="24"></picture> | the outside system a hook receives from: `linear`, `github`, `token`. Two are yardr's own and need no hook: `yardr`, this yard's bead events, and `peer`, what a linked yard says of the beads this yard has at it |
| thread | a conversation in a source that a crew member takes part in: in Linear, an issue; in `peer`, a bead of this yard that is at a linked yard |
| link | a bead's tie to an outside issue it tracks or relates to |
| peer <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-peer-light.svg"><img alt="peer" src="assets/pictograms/track-plan-peer-dark.svg" height="24"></picture> | another yard this one is linked with |
| pack <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-pack-light.svg"><img alt="pack" src="assets/pictograms/track-plan-pack-dark.svg" height="24"></picture> | a way of working as one directory: flows, groups, roles, crew members |
| pack API | the contract between a yard and a pack built outside this repository: what the pack may say in its files, run in its scripts and hear, each marked stable or internal, under an `api:` number in `pack.yaml` that rises when the stable part grows ([pack-api.md](pack-api.md)) |
| operator | the person who runs the yard; one of its users |
| user | a person of the yard: a name and an inbox |
| device | one program of a user that calls the yard from outside it, let in by a token the yard gave it ([users.md](users.md#devices)) |
| delegated run | the yardmaster running one of the operator's defining commands in its own pane, on that operator's local mail to it (`--for <sender> --mail <seq>`), recorded (`yardr delegation show`) and mailed to the operator after it runs instead of approved before; the setting `yardmaster_delegation` is its switch ([users.md](users.md#the-yardmaster-for-the-operator)) |
| edge <picture><source media="(prefers-color-scheme: dark)" srcset="assets/pictograms/track-plan-edge-light.svg"><img alt="edge" src="assets/pictograms/track-plan-edge-dark.svg" height="24"></picture> | a service that stands in front of yards and hands them the webhooks sent to it; yardr runs one at https://my.yardr.dev. A yard connects to one with `yardr edge connect`, pins its key when it does, and still verifies every webhook itself |
| edge link | the one WebSocket a yard's server keeps open to its edge while the `edge` setting is set, so that what reaches the edge for the yard comes down it with no port of the yard's own; it is the yard's only once each end has signed the other's fresh nonce, and every request on it is signed by the edge |
